Example Platform · Development setup

First-run walkthrough,
from empty repo to live shop.

Six short steps. Each one opens the exact page you need — Stripe keys, Google Cloud Console, and your own local dashboard — so nothing is a dead end.

🧰

Step 01 · One time

Check the tools on this machine

The stack runs in Docker. You need these installed, then nothing more.

1
Docker Engine + Compose v2 Required

Runs the Postgres, Strapi CMS, Spring Boot backend, and Traefik edge router as one stack.

2
Python 3.10 or later Required

Drives the setup script that generates secrets and starts the services.

3
Git + an internet connection Required

First build pulls the application images, so a working network is needed.

docker --version   # Docker 24+
docker compose version   # v2.x
python3 --version    # 3.10 or later
Docker install docs Python install
🚀

Step 02 · ~5 minutes

Start the full stack with one command

The script generates secrets, boots every service, and only finishes once each health check passes.

1
Run the setup script

From the repository root. It writes .env (private secrets) and config/business.json (your company details), then starts Docker Compose.

2
Enter your business profile

Company name, contact email, time zone, language and currency. Address and phone are optional. Confirm with yes.

3
Wait for health checks

The script waits for every container to become healthy, then probes the Storefront, Admin and CMS routes through Traefik. It stops on any failure.

sh setup.sh

Step 03 · One time

Create the first technical administrator

This is a Strapi CMS account. It is separate from the operator sign-in used by the Angular admin.

1
Accept the Strapi administrator setup

When the script asks, enter yes. It opens Strapi's interactive administrator creation.

2
Enter name, email and password

Use a strong password (14+ characters). It is stored as a BCrypt hash in Postgres — never in plain text.

3
Sign in to the CMS later

Open Strapi after setup. The Angular admin uses a separate local operator account.

Angular operator (local)Orders, products, shop settingsVia admin.localhost

Step 04 · Payments go live here

Connect Stripe (sandbox first)

Two secrets plus a signed webhook. Grab both from the same Stripe dashboard — no guessing.

1
Open your Stripe account Register / sign in

Create a business account, or use the existing one. Choose test mode while you verify checkout and webhooks.

2
Copy the Secret key (sk_test_…) API keys

Found under Developers → API keys. This is the secret key — never expose it to the browser.

3
Create the webhook endpoint Developers → Webhooks

Point it at your local listener, forward to the backend, and copy the signing secret (whsec_…). Select the events below.

# Local webhook listener — run in its own terminal.
stripe listen --forward-to http://storefront.localhost/webhooks/stripe \
  --events checkout.session.completed,checkout.session.async_payment_failed
Add to your private .envValue from StripeRequired?
STRIPE_SECRET_KEYThe secret key sk_test_… (or sk_live_…)Required
STRIPE_WEBHOOK_SECRETThe webhook signing secret whsec_…Required

Step 05 · Bookings sync + email

Connect Google (optional but recommended)

Calendar import keeps double-bookings impossible; Gmail sends confirmations. Both use one OAuth client.

1
Create a Google Cloud project Console → Projects

One project per business. This is where APIs and credentials live.

2
Enable the APIs you need API Library

Turn on the Google Calendar API. Enable the Gmail API only if you will send email (the platform requests gmail.send, never mailbox read).

3
Configure the OAuth consent screen OAuth consent

Set the app name and your support email so Google can show a proper permission page.

4
Create an OAuth client (Web) Credentials

Type Web application. Add the local redirect URI below (plain localhost — Google Cloud rejects admin.localhost). Copy the Client ID and secret.

# Authorized redirect URI for local use (add the production HTTPS one before deploy):
http://localhost/login/oauth2/code/google
Add to your private .envValueRequired?
PLATFORM_GOOGLE_ENABLEDtrueRequired to connect
GOOGLE_CLIENT_IDYour OAuth client ID from the ConsoleRequired
GOOGLE_CLIENT_SECRETYour OAuth client secret (keep out of Git)Required
PLATFORM_ADMIN_BASE_URLhttp://localhostMust match the registered URI

Google Cloud rejects .localhost subdomains with a top-level-domain error, so the local redirect uses plain localhost. Traefik routes both http://admin.localhost and http://localhost to the admin UI.

Build the Google environment block

This builder does not save input. Clear this page before screen sharing if it contains a client secret.

Equivalent to: openssl rand -base64 32

Put this block into your private .env at the repository root, then restart the backend and admin.

Create Cloud project API Library OAuth client Calendar API Gmail scopes

Then in the admin, open Connections → Connect Google services and map each resource to a calendar.

Step 06 · Go live with confidence

Verify, then place a test order

A green status plus one real sandbox purchase is the whole definition of done.

1
Read the system checks in the admin

Open System → Checks. A row that says “configuration present” only means a value exists — it does not prove the connection works. Run a live action to confirm.

2
Place a sandbox order end-to-end

Buy one product on the Storefront, pay with card 4242…123, and confirm the webhook flips the order to PAID and decrements stock.

3
Refund it (optional)

From the admin, refund the order to confirm restock and the Stripe refund path.

Start over with a clean slate

This removes all local data (databases, uploads) and re-runs the setup. Your Google Cloud client ID and secret stay valid.

# Full reset — new company details and new secrets:
docker compose down -v
rm -f .env config/business.json .setup-state.json
sh setup.sh

Keep the company details and existing secrets? Remove only the state flag, then re-run the setup.

# Data reset — wipe databases and uploads, keep .env:
docker compose down -v
rm -f .setup-state.json
sh setup.sh

After a full reset, add the Stripe keys (Step 04) and the Google credentials (Step 05) to the new .env by hand.
