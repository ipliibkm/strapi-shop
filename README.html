Calendar connection

Create a Google client ID

Complete each Google Cloud step in order. Google grants Calendar and Gmail send access. It does not sign administrators into the platform.

Step 1

Create or select a Google Cloud project

  1. Open Google Cloud Console.
  2. Select an existing test project or create a new project.
  3. Use separate Google Cloud projects for test and production environments.
Open project creation
Google recommends separate OAuth clients and projects for test and production use.

Step 2

Enable Google Calendar API

  1. Select your Google Cloud project.
  2. Open APIs & Services.
  3. Find Google Calendar API.
  4. Select Enable.
Open Calendar API

Step 3

Configure Google Auth Platform

  1. Open Google Auth Platform.
  2. Set the application name and support email under Branding.
  3. Select External under Audience for normal Google accounts.
  4. Add each administrator under Test users.
  5. Add the Calendar event, calendar-list, and Gmail send scopes under Data Access.
https://www.googleapis.com/auth/calendar.events
https://www.googleapis.com/auth/calendar.calendarlist.readonly
https://www.googleapis.com/auth/gmail.send
Open Google Auth Platform
If you use Google Workspace, your administrator can select an internal audience when the organization permits it.

Step 4

Create the OAuth client

  1. Open Google Auth Platform > Clients.
  2. Select Create client.
  3. Select Web application.
  4. Enter a clear name, such as Example local admin.
  5. Add the exact authorized redirect URI below.
  6. Select Create.
http://localhost/login/oauth2/code/google
Open OAuth clients
Exact match required: A different host, port, path, or trailing slash causes redirect_uri_mismatch.
Why localhost: Google Cloud rejects admin.localhost with a top-level-domain error, so the local URI uses plain localhost. Set PLATFORM_ADMIN_BASE_URL=http://localhost in the local environment file so the backend sends exactly that URI. Traefik routes both hostnames to the admin UI.

Step 5

Store credentials in the local environment

  1. Copy the client ID from Google Cloud.
  2. Copy the client secret.
  3. Generate separate 32-byte keys for Google and Strapi tokens.
  4. Open the repository .env file.
  5. Add the generated configuration block.
Keep the secret private: Do not commit .env. Do not put the client secret in Angular code or browser storage.
Build the configuration

Step 6

Recreate the application containers

Docker Compose reads .env when it creates each container. Recreate the backend and admin after each authentication configuration change.

docker compose up -d --build --force-recreate backend admin

Wait until both services report healthy.

docker compose ps backend admin

Step 7

Connect a Google account

  1. Open the operations admin.
  2. Sign in with a local Strapi Super Admin account.
  3. Open Connections.
  4. Select Connect Google services.
  5. Approve Google Calendar event management and calendar-list access.
  6. Map each platform resource ID to a writable calendar.
Open operations admin
The backend encrypts OAuth and Strapi session tokens in PostgreSQL. Administrator sign-out and Google disconnect are independent operations.

Troubleshooting

Verify the connection

Use these checks before you change application code.

Authentication mode

The response must contain "mode":"strapi" and "enabled":true. googleCalendarEnabled reports Calendar configuration.

curl -sS http://admin.localhost/api/v1/auth/config

Container values

Check non-secret values inside the backend container.

docker compose exec backend printenv PLATFORM_GOOGLE_ENABLED PLATFORM_ADMIN_BASE_URL
The operations admin rejects my credentials

Use a local Strapi administrator account. Wait five minutes after repeated failures. Google credentials cannot sign in to the operations admin.

I can open Content but no other section

Assign the Strapi strapi-super-admin role when the account requires full platform administration.

Google reports redirect_uri_mismatch

Register exactly http://localhost/login/oauth2/code/google. Do not add a trailing slash. The backend must send the same URI: set PLATFORM_ADMIN_BASE_URL=http://localhost in the local environment file.

Google reports that the app is being tested

Add the selected Google account to the OAuth consent screen test-user list.

The backend cannot decrypt the saved connection

Restore the original PLATFORM_OAUTH_TOKEN_ENCRYPTION_KEY. If the key is lost, disconnect the database record and complete Google consent again.

I want to wipe all data and start clean

Stop the stack, delete its volumes, then re-run setup. To reset the company details and secrets as well, remove them first:

docker compose down -v rm -f .env config/business.json .setup-state.json sh setup.sh

Keep the company details and existing secrets? Remove only the state flag:

docker compose down -v rm -f .setup-state.json sh setup.sh

System boundaries

Architecture rules

The monorepo contains logical modules. Each component has one primary responsibility.

Content

Strapi owns editorial content and CMS-managed tables. It does not own orders, inventory, payments, or booking allocation.

Transactions

Spring Boot owns booking and commerce transactions. Liquibase changes application-owned tables only.

Identity

Local Strapi accounts authenticate administrators. Strapi roles control access. Google OAuth grants Calendar and Gmail send access. It does not grant mailbox read access. The backend keeps all provider tokens out of Angular browser storage.

Calendar providers

The booking domain uses provider-neutral ports. Google is the current adapter. Microsoft Calendar can be added without Google branches in booking services.

Payments

The payment provider settles payments. The backend verifies signed webhooks and does not trust browser totals or redirects.
